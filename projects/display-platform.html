Centralized Multi-Screen Display Platform

A server-driven media platform for distributing visual content to multiple unattended displays while monitoring client health, current media and remote refresh state.

PythonFlaskSocket.IORaspberry PiLinux
Centralized Multi-Screen Display Platform Server-driven media distribution, client health monitoring and Raspberry Pi display endpoints.

Problem

Multiple screens needed a consistent way to receive updated media without requiring manual configuration or intervention at each display.

Solution

A centralized server rendered/distributed media while connected clients reported status and could be refreshed remotely.

Architecture

Media Folders→Python / Flask Server↔ Socket.IO↔Raspberry Pi Clients→Displays

System design

Simple content updates, visible client health

Media workflow

Operator workflowUsers could place images or video into designated folders rather than configure every screen individually.
Automatic updatesFolder monitoring rebuilt the media list and Socket.IO pushed updates to connected displays.

Display monitoring

HeartbeatsClients periodically reported screen identity, current media and last-seen state.
DashboardA browser-based manager showed Online / Stale / Offline status, current media and refresh controls.

Unattended reliability

Video handlingPlayback logic included watchdog/fallback behavior so a failed or stalled video would not permanently stop the slideshow.
Client operationRaspberry Pi/Linux endpoints were used as unattended display clients, including a large-format LED display endpoint.
